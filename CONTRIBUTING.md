# Contributing to LegalBuddy

First off, thank you for considering contributing to LegalBuddy! It's people like you that make LegalBuddy such a great tool.

## How to Contribute

### Reporting Bugs
If you find a bug, please create an issue on GitHub and provide as much detail as possible, including:
* A clear and descriptive title.
* Steps to reproduce the issue.
* Expected behavior vs. actual behavior.
* Details about your environment (OS, Node version, Python version, Docker vs Local).

### Suggesting Enhancements
We welcome suggestions for new features or improvements. When suggesting an enhancement, please include:
* A clear description of the feature and why it would be useful.
* Any potential alternatives you've considered.

### Pull Requests
1. Fork the repository and create your branch from `main`.
2. Ensure you have followed the setup instructions in the `README.md` and that the application runs locally.
3. Make your code changes.
4. If you've added code that should be tested, add tests!
5. Ensure your code lints and is properly formatted.
6. Issue that pull request!

## Development Setup

To get started with local development, please refer to the **Setup & Installation** section in the [README.md](./README.md).

## Code Style
* **Python**: We follow standard PEP-8 guidelines. Please ensure your code is clean and properly documented.
* **Next.js/TypeScript**: We use strict TypeScript configurations and ESLint for the frontend. Please resolve any linting warnings before submitting your PR.
